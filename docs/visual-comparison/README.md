# Визуальное сравнение с PlantUML

В каждом листе **слева — наш рендер, справа — эталон PlantUML**.
Сверху листа идёт подпись: синяя черта и «НАШ РЕНДЕР (plantuml-rs)» слева,
зелёная и «ЭТАЛОН PlantUML (plantuml.com)» справа.

Ориентация проверена измерением, а не на глаз: левая половина каждого листа
попиксельно совпадает с растеризацией нашего SVG (разница 0.00), правая —
с эталоном (0.00).

Эталоны получены с plantuml.com (v1.2026.9beta4) скриптом
`tests/golden/fetch_references.py`.

## Как получено

```bash
# наш рендер
cargo run --release -p plantuml-core --example=<кейс>
# эталоны — уже лежат в tests/golden/reference/
# raster
rsvg-convert -w 600 <наш>.svg -o <наш>.png
rsvg-convert -w 600 <эталон>.svg -o <эталон>.png
magick <наш>.png <эталон>.png +append -bordercolor gray -border 2 <тело>.png
python3 - <<'EOF'   # полоса-подпись сверху
...
EOF
magick <подпись>.png <тело>.png -append <лист>.png
```

Суммарное отклонение: **55 px по ширине, 19 px по высоте** на 20 диаграмм.
Было 297/314 до начала работы над планом.

По ширине из 55 px **36 дают deployment_basic и state_simple** — это
маршрутизация GraphViz. Остаток — запас холста sequence-диаграмм: PlantUML
добавляет справа 10, 16, 20 и 30 px в четырёх разных случаях, одной
константой это не описывается, при этом само содержимое совпало.

## О чём говорят крупные расхождения

`deployment_basic` и `state_simple` отклоняются на ~18 px по ширине —
это 36 из 50 px суммарного отклонения. Причина одна: **маршрутизация
рёбер GraphViz**. PlantUML строит эти диаграммы через GraphViz (dot),
который проводит связи кривыми в обход узлов. Воспроизведение алгоритма
dot — отдельная большая задача, поэтому расхождение здесь ожидаемо и не
является дефектом раскладки.
